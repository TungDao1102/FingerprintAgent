# Plan 02: Configuration + CORS + Error Responses

**User story:** As a developer, I want to configure the agent via `config.json` (port, host, CORS mode) so that I can change runtime behavior without recompiling, and I want CORS protection working so that unauthorized origins cannot access the API.

**Goal:** Replace hardcoded values from Plan 01 with `config.json`-driven configuration. Implement `CorsMiddleware` with wildcard/allowlist modes. Add comprehensive validation + error responses. Wire config into `HttpServer` startup.

---

## Task 01-02-02: CorsMiddleware + Wire Config into HttpServer Request Handling

```xml
<task id="01-02-02" type="tdd">
  <description>
    Create `CorsMiddleware` class implementing wildcard and allowlist modes with OPTIONS preflight
    handling. Wire the middleware into `HttpServer` request dispatch. Integrate `ConfigLoader`
    into `Program.cs` so that `HttpServer` reads host/port from config.

    TDD gates for CorsMiddleware:
    - RED: Write tests for `CorsMiddleware.HandleCorsPreflight()` — OPTIONS with Origin returns
      204 with CORS headers. OPTIONS without Origin returns false (no handling).
      Tests for `ApplyCorsHeaders()` — wildcard mode sets `Access-Control-Allow-Origin: *`,
      allowlist mode sets origin if allowed, returns 403 if disallowed origin.
    - GREEN: Implement `CorsMiddleware` per algorithm in RESEARCH.md §2.7.
    - REFACTOR: Ensure `HashSet<string>` is `StringComparer.OrdinalIgnoreCase` for origin comparison.
  </description>
  <read_first>
    - .planning/phases/01-foundation-windows-service-http-api-skeleton/01-RESEARCH.md (§2.7 CORS in Raw HttpListener, §2.6 Config.json Schema)
    - .planning/phases/01-foundation-windows-service-http-api-skeleton/01-PATTERNS.md (item 8)
    - .planning/phases/01-foundation-windows-service-http-api-skeleton/01-CONTEXT.md (D-12, D-13)
    - .planning/REQUIREMENTS.md (API-05, SEC-01, SEC-02)
    - Current `src/FingerprintAgent/Api/HttpServer.cs` (to see request dispatch structure)
    - Current `src/FingerprintAgent/Program.cs` (to see where to plug config)
  </read_first>
  <acceptance_criteria>
    - OPTIONS `/api/capture` with `Origin: http://example.com` returns 204 with headers:
      `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods` includes "POST, GET, OPTIONS",
      `Access-Control-Allow-Headers` includes "Content-Type"
    - In wildcard mode, GET/POST responses include `Access-Control-Allow-Origin: *`
    - In allowlist mode with `allowedOrigins: ["http://trusted.com"]`:
      - OPTIONS with `Origin: http://trusted.com` → 204 with `Access-Control-Allow-Origin: http://trusted.com`
      - OPTIONS with `Origin: http://evil.com` → 403 Forbidden
    - When `config.json` has `http.port: 5044`, service starts on port 5044
    - When `cors.mode` is set to `"allowlist"` and no origin matches, request returns 403
    - All existing Plan 01 acceptance criteria still pass after wiring config
  </acceptance_criteria>
  <action>
    - Create `src/FingerprintAgent/Api/CorsMiddleware.cs` — class with constructor taking `string mode, string[] allowedOrigins`.
      Store `_allowedOrigins` as `HashSet<string>(StringComparer.OrdinalIgnoreCase)`.
      Method `HandleCorsPreflight(HttpListenerRequest request, HttpListenerResponse response)`:
      if `request.HttpMethod != "OPTIONS"` return false. Read `Origin` header. If null/empty return false.
      Call `ApplyCorsHeaders`. If mode=allowlist and origin not in `_allowedOrigins`: set 403, close, return true.
      Otherwise: set 204, return true.
      Method `ApplyCorsHeaders(HttpListenerResponse response, string origin)`: if wildcard → set `Access-Control-Allow-Origin: *`.
      If allowlist and allowed → set `Access-Control-Allow-Origin: origin` and `Vary: Origin`.
      Also set `Access-Control-Allow-Methods: POST, GET, OPTIONS` and `Access-Control-Allow-Headers: Content-Type` and `Access-Control-Max-Age: 86400` on non-preflight responses.
    - Modify `src/FingerprintAgent/Api/HttpServer.cs`:
      - Add `CorsMiddleware` field, accept `AgentConfig` in constructor.
      - In `HandleRequest()`, call `_cors.HandleCorsPreflight(request, response)` first — if true, return.
      - Then call `_cors.ApplyCorsHeaders(response, request.Headers["Origin"])` for actual requests.
      - Read `host` from `config.Http.Host`, `port` from `config.Http.Port` for listener prefix.
    - Modify `src/FingerprintAgent/Program.cs`:
      - In console mode, call `ConfigLoader.Load()` first to get `AgentConfig`.
      - Pass `AgentConfig` to `HttpServer` constructor (instead of hardcoded host/port).
      - Wrap config loading in try-catch; print fatal error and exit if config is invalid.
    - Modify `src/FingerprintAgent/Api/CaptureHandler.cs`:
      - Add comprehensive error response for `INVALID_REQUEST` (missing fields, malformed JSON, empty body).
      - Ensure all error responses set HTTP status code (400 for invalid request, 500 for capture failure).
    - Create `tests/FingerprintAgent.Tests/CorsMiddlewareTests.cs` with [Fact] methods:
      `Preflight_WithOrigin_Returns204`,
      `Preflight_WithoutOrigin_ReturnsFalse`,
      `Preflight_WildcardMode_SetsAsterisk`,
      `Preflight_AllowlistMode_AllowedOrigin_Returns204`,
      `Preflight_AllowlistMode_DeniedOrigin_Returns403`,
      `ActualRequest_Wildcard_SetsAsterisk`,
      `ActualRequest_Allowlist_AllowedOrigin_SetsOriginHeader`,
      `ApplyCorsHeaders_NoOrigin_DoesNothing`.
  </action>
</task>
```
