# 04-01 PLAN: ConfigMerger + ProgramData Path Migration + UpdateConfig POCO

## Goal

Move runtime `config.json` from the install directory (`AppDomain.CurrentDomain.BaseDirectory`) to `C:\ProgramData\FingerprintAgent\config.json` (writable without admin, survives upgrades). On upgrade, smart-merge the new template's keys into the user's existing config (additive only — user values preserved, user deletions respected). Add the `UpdateConfig` POCO for the auto-update feature so it can be configured in the same `config.json` (D-13/14/15). Wire `ConfigFileWatcher` to watch the ProgramData path instead of the install-dir path.

## Scope

D-13, D-14, D-15, D-33, D-34, D-35, D-36, D-37.

Supports DEP-01 (package contents) and DEP-04 (smoke test) by establishing the ProgramData config location that the MSI seeds (Plan 04-02) and that the auto-update Timer (Plan 04-03) reads.

Backward compat: the FIRST agent start after upgrade may find config in the OLD install-dir path. Plan must handle this — if ProgramData config missing AND install-dir config present, copy the install-dir config to ProgramData and continue. Otherwise we'd silently lose IT customizations on first upgrade.

## Decisions Carried Forward

From Phase 3 CONTEXT (D-08): "bad parse / missing sections keep old config, logs error, does NOT throw." ConfigLoader must preserve this behavior.

From Phase 3 CONTEXT (D-09): "active adapter stays the same, but new priority applies on next failure." ConfigFileWatcher priority reload semantics unchanged — only the watched path moves.

- Do NOT introduce DI containers (per AGENTS.md "No DI container (despite package)") — ConfigLoader stays static
